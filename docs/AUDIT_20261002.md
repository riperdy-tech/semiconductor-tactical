# Implementation Audit — 2026-10-02

## Executive finding

The repository is a useful **software scaffold**, but it is **not yet the historical research engine described by the project specification**.

The most important problem is not execution convenience: the current CLI runs synthetic fixture bars. Therefore the headline backtest/research commands cannot answer the original question about the Reddit trader.

## Critical findings

### C1 — Current CLI is synthetic-only

\`src/tactical_engine/__main__.py\`, \`src/tactical_engine/research/cli.py\`, and \`src/tactical_engine/research/report_generator.py\` generate data with \`generate_synthetic_bars()\`.

There is currently no historical equity-data ingestion path in the CLI.

**Impact:** a successful report is a software smoke test, not evidence about the strategy.

**Required before historical conclusions:** implement a documented historical data adapter and run manifest containing actual data hashes/provider/date range.

### C2 — Leverage is not actually wired into sizing

\`PortfolioConfig.max_gross_leverage\` exists, and the comparison code varies it, but \`calculate_position_size()\` does not use \`max_gross_leverage\`.

**Impact:** the leverage sensitivity experiment does not actually represent 1.0×/1.5×/2.0× leverage as claimed.

### C3 — Layered entries are not implemented

The spec allows 2–3 layers, but \`run_backtest()\` skips entry when \`sym in tracker.positions\`.

**Impact:** \`max_layers\` currently does not control actual layered entries.

### C4 — 2× ETF exposure is only configuration

\`two_x_etfs\` exists in configuration, but the backtest path does not add those instruments to the universe or trade them.

**Impact:** the literal-clone description overstates current implementation.

### C5 — Sector/regime filter is not actually sector/regime data

\`generate_pullback_signals()\` uses the individual symbol's own \`trend_ok\` when \`sector_filter=True\`.

That is not a semiconductor-sector filter and is not an RS2/MRI regime adapter.

**Impact:** \`regime_adapted\` is currently not the specified research variant.

### C6 — Several configured filters are unused

\`relative_volume_filter\` and \`event_filter\` are defined in configuration but are not applied by the signal generator.

**Impact:** configuration suggests behavior the engine does not implement.

### C7 — Option experiment is not yet historical-valid

The option provider requires exact timestamp equality. The CLI does not load historical option chains. Covered-call accounting is also incomplete: there is no true repurchase-on-pullback implementation, and expiration bookkeeping uses placeholder timing/valuation behavior.

**Impact:** options should remain \`UNVALIDATED\` until an actual historical option dataset and execution model are present.

### C8 — Cost accounting has a likely slippage double-count

\`ExecutionSimulator\` embeds slippage into \`fill.price\`, while \`PortfolioTracker.apply_fill()\` also subtracts \`fill.slippage\` from sell-side \`net_pnl\`.

The cash ledger and trade-level P&L therefore do not use the same cost convention.

**Required:** define one canonical accounting convention and add a regression test that verifies cash P&L equals trade P&L after commissions and slippage.

### C9 — Research commands are too easy to mistake for real research

The command names do not make it obvious that they use synthetic data.

The new \`run.ps1\` therefore labels all current backtest/research outputs explicitly as **fixture-only**.

## What was added

- \`run.ps1\`: one-command Windows runner.
- \`run.bat\`: double-click launcher.
- \`.github/workflows/ci.yml\`: automatic tests and smoke runs on every push/PR, across Windows and Ubuntu with Python 3.11/3.12.
- This audit document.

## Operator workflow

For now:

    .\run.ps1 doctor
    .\run.ps1 full

\`full\` is intentionally a **software validation run**, not a claim that the tactical strategy works.

Once historical data ingestion exists, add a separate command such as:

    .\run.ps1 historical

That command should refuse to run unless the required data contracts are satisfied.

## Definition of readiness for the actual research question

The project should not report a conclusion about the Reddit strategy until:

1. real historical equity bars are available;
2. the execution/cost model is tested;
3. leverage is implemented rather than configured-only;
4. layered entries are implemented or explicitly excluded;
5. semiconductor sector/regime features are real;
6. historical option data exists before options conclusions are made;
7. out-of-sample periods are genuinely untouched;
8. the comparison report distinguishes fixture tests from market-data results.
